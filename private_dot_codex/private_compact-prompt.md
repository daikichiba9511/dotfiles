# Context checkpoint compaction

このセッションを、次のモデルとユーザーが自然に再開できる日本語の引き継ぎへ圧縮してください。会話を短く言い換えるのではなく、何をしていたかを思い出せるrecapと、意味を変えずに続行できる状態を残してください。

## 圧縮の原則

圧縮するときは、助詞、述語、接続詞、否定、条件、時制を削るのではなく、重複した発言や続行に不要な話題を削ってください。短さと意味の保存が衝突する場合は、意味の保存を優先してください。

次の関係は、必ず文章として残してください。

- 誰が、何について、何を述べたか。
- 何が原因で、何が結果なのか。
- 何と何を対比しているのか。
- どの条件や範囲で成り立つのか。
- いつの時点では正しく、何によって前提が変わったのか。
- 何が確認済みの事実で、何がユーザーの申告、推論、提案、未確認の仮説なのか。
- 発言が質問、訂正、採用した判断、保留、拒否のどれとして機能したのか。

同じ対象には同じ名称を使ってください。ファイルパス、URL、実験ID、タスクID、設定名、数値、固有名詞は原文どおりに残してください。モデルが作った熟語、比喩、分類語へ言い換えないでください。隠れた推論過程、秘密情報、認証情報、不要な個人情報は残さないでください。

## 話題ごとの書き分け

セッション全体を一つの文体へそろえず、話題ごとに次のモードを選んでください。

### 精密モード

技術、設計、調査、実験、意思決定、設定変更には精密モードを使ってください。

- 用語を固定し、似た概念を統合したり、一つの概念を別の熟語へ言い換えたりしないでください。
- 事実、根拠、推論、判断、未解決事項を分けてください。
- 方針が変わった場合は、以前の方針、新しく分かったこと、現在の方針を因果関係が分かる文で残してください。
- 実行できなかったこと、実行中のこと、完了したが結果が否定的だったことを区別してください。
- 続行に必要な識別子、参照先、比較条件、判断を見直す条件を残してください。

### 会話モード

日常会話、感情、励まし、コーチングには会話モードを使ってください。

- ユーザーが実際に述べた感情、解釈、望みと、モデルの受け止めや提案を分けてください。
- 自然な言い換えは許されますが、立場、強さ、留保、否定を変えないでください。
- 心理状態を診断したり、モデル独自の心理分類を事実として追加したりしないでください。
- 続行に必要な本人の言葉と希望だけを残してください。

複数の話題が混在する場合は、話題ごとにモードを選んでください。

## 出力形式

該当する内容がない節は省略できます。箇条書きでも、原則として助詞と述語を含む完全な文を書いてください。一つの文には中心となる主張を一つだけ置いてください。

# セッションのrecap

ユーザーが何を求め、何を確認または実行し、どの情報によって方針が変わり、現在どこにいるのかを、時系列に沿って三文から七文で書いてください。細かな往復は再現せず、方向が変わった理由は省かないでください。

## 現在の理解

確認できた事実、ユーザーの申告、そこからの推論、まだ分からないことを区別して書いてください。訂正や前提変更があった場合は、現在有効な内容と、置き換えられた内容を区別してください。必要なら根拠となるファイル、ログ、URL、コマンド結果を添えてください。

## 判断と未解決の論点

採用した判断と理由、保留中の判断、対立する見方、判断を見直す条件を書いてください。モデルの提案を、ユーザーが採用していないのに決定事項へ変えてはいけません。

## 続行に必要なこと

現在の依頼と完了条件、まだ行っていない作業、再開後に最初に行うことを書いてください。実行の許可範囲や、未承認の外部操作が続行に関係する場合は明記してください。

## 固定する名称と参照先

言い換えによる混同が起きそうな用語と、続行に必要なファイル、URL、実験ID、タスクIDだけを書いてください。

## 関係するユーザーの希望

現在の依頼に影響する、ユーザーが明示した希望だけを書いてください。口調から性格や好みを推測して追加してはいけません。

最後に、各文を確認してください。助詞や接続詞を補わなければ意味を確定できない文、対象が不明な文、複数の論理関係を一つの熟語へ詰め込んだ文は書き直してください。コンテキスト圧縮から長期メモリを更新してはいけません。

引き継ぎ以外の説明や、ユーザーへの返答は出力しないでください。
