# 日本語技術文書をリライトする

既存原稿の意味、確認済みの事実、引用、コードの挙動を保ちながら、読み手が論理を追える文章へ直接編集する。
このSkillだけで通常のリライトを完結させる。
新規生成には `japanese-tech-generation`、論証構造の組み替えには `argument-gap-edit`、編集しない指摘には `prose-lint` を使う。

## 編集範囲を固定する

編集前に、対象ファイルまたは対象範囲と、次のどこまで変更してよいかを確認する。

- 表記と文法だけ
- 文と段落の書き換え
- 見出しと節構成まで

指定がなければ、主張と節順を保ち、文と段落までを編集する。
資料にない事実、因果、数値、人物像を補わない。

## 編集する

1. 各段落の主張を一つに絞り、冒頭で話題を特定する。
2. 因果を述べる文には、なぜそうなるかの機構を残す。
3. 新しい専門用語と略語は初出で定義し、同じ語を同じ意味で使う。
4. 推定、可能性、反実仮想を、根拠なく断定へ変えない。
5. 同じ主張の言い換え、空虚な予告と総括、回収しない前方参照を削る。
6. 段落の役割を変えない範囲で、文の順序と接続を整える。
7. 編集後に原文と照合し、意味や事実を変えた箇所がないか確認する。

## 文章規範

- Markdownでは一文ごとに改行し、段落間に空行を置く。
- 一段落には一つの話題だけを置く。
- 見出しは節の対象または問いを具体的に示す。
- 用語の初出は必要なら太字で定義し、以後は表記を統一する。
- コード、ログ、設定断片はコードブロックに置く。
- 日本語の地の文でダッシュ類を補足記号として使わず、括弧か別文にする。
- 「重要なのは」「多角的に」「深掘りする」など、内容を増やさないLLM口調を使わない。
- 強調、比喩、修辞疑問、決め台詞を繰り返さない。
- 未確認事項を滑らかな説明で埋めず、確認できないことを明示する。
- 読者が後で使わない固有名や細部を増やさない。

## 完了条件

- 主張、事実、引用、コードの意味が原文から変わっていない。
- 各段落の話題と前後関係を一読で追える。
- 専門用語の指す対象と不確実性の表現が一貫している。
- 重複した主張と空虚な接続表現が残っていない。
- 依頼された範囲を越えて節構成を変えていない。
