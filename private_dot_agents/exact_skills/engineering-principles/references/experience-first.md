# Experience First

**Apply when:** product, UX, API-ergonomics, or feature-scope tradeoffs come up.

**Rule:** when implementation convenience conflicts with the consumer's experience, choose the experience.

- Every feature, control, and option must justify itself. Ship fewer polished things over more rough ones.
- Prototype before committing; design decisions are cheaper in throwaway code than in production code.
- Get the details right: feedback, error states, alignment, transitions, naming.
- Tighten the core loop. Everything serves the central workflow or gets out of the way.

The user is whoever consumes the work: the end user of a UI, the colleague who imports a library or API, and the engineer who maintains the code next. Explain impact from their point of view.

[foundational-thinking](foundational-thinking.md) governs the order of work; this principle governs the target.
