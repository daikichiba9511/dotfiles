# 表現の選択規則

本文の理解を進める場合だけ、文章以外の表現を追加する。

| 表現   | 選ぶ条件                                               | 追加する説明                     |
| ------ | ------------------------------------------------------ | -------------------------------- |
| 順序図 | 三つ以上の段階の順序や因果を同時に確認する必要がある   | 各段階の説明と図全体の結論       |
| 数式   | 量同士の依存関係または変化を正確に示す必要がある       | 記号の意味、式を読む順序、数値例 |
| コード | 実行順、入力と出力、境界条件を構文で確認する必要がある | 実行条件、期待する出力、変更点   |
| 表     | 同じ基準で三項目以上を比較する必要がある               | 比較から得られる判断             |
| 文章   | 定義、因果、判断理由を説明する                         | 必要に応じて具体例               |

一文または短い箇条書きで関係が明確になる場合は図を作らない。
計算結果を一度示せば足りる場合は数式を作らない。 実装詳細が概念理解を妨げる場合はコードを作らない。

## 順序図

順序図は `learning.json` の `diagrams` に保存する。
各段階に短いラベルと、何が変化するかを述べた説明を付ける。 矢印だけに因果を担わせず、`caption`
で図全体の意味を書く。

## 数式

数式を出す前に、式が答える問いを書く。 数式の直後で、すべての記号を定義する。
値を代入した例を一つ示し、結果が何を意味するかを書く。

## コード

省略記号だけの疑似コードを、実行可能なコードとして示さない。
実行可能なら実行方法と期待する結果を書く。 説明用の断片なら、どの部分を省略したかを明記する。

## HTML

見た目だけを変えるカードや色分けを、概念の区別として使わない。
色を使う場合も、見出し、ラベル、文章で同じ区別を示す。 本文理解に必要な前提は折り畳まない。
折り畳めるのは追加例、詳しい導出、参考情報に限る。
