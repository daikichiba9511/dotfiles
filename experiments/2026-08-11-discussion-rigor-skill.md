# discussion-rigor Skill 実験

- 日付: 2026-08-11
- ブランチ: `experiment/discussion-rigor-skill`
- 判定: 廃止

## 目的

ユーザーから推論のずれや迎合を指摘されたとき、すぐに計画や同意へ進まず、主張を正確に捉え直してから独立した見解を返す手順を Codex Skill として定義する。

## 仮説

「理解の再構成 → 異議の分類 → 独立した判断」の順序を明示すれば、表面的な同意や例示の過剰な字義化を減らせる。一方、通常の設計・調査・実装依頼をトリガーから除外すれば、既存の専門 Skill との競合を抑えられる。

## 変更

- 誤解の修復、非迎合、根拠を伴う独立判断を一つのワークフローにした。
- Skill の説明に肯定トリガーと除外条件を併記した。
- 共有 Skill として `~/.agents/skills/` に配置し、Codex 固有ディレクトリの重複を削除した。

## 評価

トリガー境界を次の会話例で静的に監査した。

| 入力の要旨 | 期待する経路 | 判定 |
| --- | --- | --- |
| 「話を合わせているだけで論点に答えていない」 | discussion-rigor | 適合 |
| 「その例は用語として使ったのではない」 | discussion-rigor | 適合 |
| 「迎合せず独立した見解を述べて」 | discussion-rigor | 適合 |
| 「認証基盤の構成を設計して」 | architect | 除外を明記 |
| 「関連論文を調べて比較して」 | research-synthesis | 除外を明記 |
| 「この変更の実装計画を作って」 | plan | 除外を明記 |

配置と構造は以下で確認した。

- `chezmoi apply --force` が成功する。
- `~/.agents/skills/discussion-rigor/SKILL.md` が生成される。
- `~/.codex/skills/discussion-rigor` の重複が残らない。
- Claude の共有 Skill シンボリックリンクから同じファイルを参照できる。
- frontmatter、OpenAI UI メタデータ、`git diff --check` が静的検査を通る。

## 結果と考察

初期案は「実験方針、戦略、アーキテクチャ、調査の相談」全般をトリガーに含めており、`analysis-discus`、`architect`、`meta-perception`、`research-synthesis` と競合しやすかった。トリガーを「Codex の推論への異議・訂正」または「非迎合な議論の明示要求」に限定したことで、この Skill は専門 Skill を置き換えるものではなく、会話のずれを修復する横断的な手順として位置づけられた。

今回確認できたのは構造、配置、トリガー文言の静的妥当性までであり、実会話で迎合や過剰な確認質問がどの程度減るかは未測定である。運用中は、主張の言い換えが冗長にならないか、必要な反論まで弱めていないか、文脈不足を理由に質問へ逃げていないかを観察する。

## 運用後の再評価

2026-09-02 に実際の発火例を再評価し、この Skill を廃止した。

通常の訂正や軽い文章上の異議でも発火し、主張の言い換え、異議の分類、独立見解の提示を必須化していた。その結果、基礎モデルが状況に応じて簡潔に修正する余地を狭め、応答を儀式化する可能性があると判断した。

有用だった「訂正を立場反転の命令ではなく証拠として扱う」という原則は、短い条件付き規則として `private_dot_codex/AGENTS.md` へ移した。実験戦略とアーキテクチャの評価基準は、それぞれ `ml-iterate` と `architect` へ移した。
